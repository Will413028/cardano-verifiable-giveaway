## 前提（開工時核對過，2026-10-18；indexer 相關 2026-10-19 依 PD7 重寫）

- **會改到或取代的既有部署是否在線：** 無既有部署（README「Status」：No public deployment）。本計畫不部署後端；部署屬 MVP 計畫步驟 10，需要 Will 授權。鏈上沒有任何人依賴的承諾，協定可自由修改；上鏈後不能改的承諾已由 MVP 計畫 I3 規範。
- 後端範圍、禁止事項、帳號與保存期限依兩份 ADR：`docs/adr/2026-10-18-typescript-convenience-backend.md`、`docs/adr/2026-10-18-wallet-auth-and-bounded-retention.md`（來源：Will，2026-10-18；已確認）。
- indexer：不再使用 koios.rest。條款字面禁止系統性擷取、自動化使用與轉發（2026-10-19 步驟 9 重查，見進度表），Will 2026-10-19 決定不取得同意，改採 Blockfrost 形狀介面卡＋自架 Dolos（full archive），CLI 不設專案預設、必須以 `--indexer` 指定使用者自備的 full-archive Blockfrost 相容節點（PD7，ADR `docs/adr/2026-10-19-self-hosted-dolos-indexer.md`；已確認）。
- Dolos 的 MiniBF（Blockfrost 相容 API）事實（2026-10-19 讀 Dolos 原始碼與 `minibf.mdx`，未在本機實跑）：不需要 API key；`permissive_cors` 預設 true；`/addresses/{a}/transactions` 接受 `addr_vkh`（payment credential）；穩定版 1.6.1 沒有 `/accounts/{stake}/transactions`（只有 pre-release 1.7.0-alpha.1、2.0.0-alpha.0 與 main 有，步驟 8b 實測 404），stake credential 改用 `/accounts/{stake}/addresses`＋逐址 `/addresses/{a}/transactions`（PD9）；page×count 超過 `max_scan_items`（預設 3000）時拒絕，營運者可調高；有 Ledger-only、Sliding history、Full archive 三種儲存模式，非 full archive 的節點列舉不出舊承諾、verifier 察覺不到；不能跑在 Workers，需要一台有狀態的 VM。
- Dolos 的未知（未確認；Dolos 程式本身的行為由步驟 8b 在本機 emulator 開發鏈上量，preprod 規模與資源由步驟 8c 在 VM 上量）：preprod full archive 的磁碟與同步時間；`addr_vkh` 與 stake 帳戶列舉的分頁與排序是否穩定（同一區塊多筆時的次序）；stake 帳戶列舉是否列出 stake 只出現在 input 的交易；剛上鏈交易的 `/txs/{h}/cbor` 回 404 還是空值；主網 RAM（調查寫 < 2 GB，沒有出處）；verifier 如何偵測使用者節點的歷史不完整。
- 公開部署 Dolos 與後端需要 Will 授權（MVP 計畫步驟 10）。本機不跑 preprod Dolos：TxPipe 的 preprod full 快照壓縮後 10.17 GB（2026-10-19 實測 HTTP `content-length`，`dolos-snapshots.txpipe.cloud/v3/1/full/latest.tar.gz`，最後更新 2026-06-11），Mithril 的 preprod 節點資料解壓後 20.04 GB（同日查 Mithril aggregator），Will 2026-10-19 決定本機不佔這個空間。本機只跑 Dolos 的 emulator 模式（`upstream` 設為 Emulator，從 mempool 自行產生區塊、沒有既有鏈歷史，v1.6.1 原始碼 `src/sync/emulator.rs`）；preprod Dolos 改在 VM 上量（步驟 8c，開 VM 需要 Will 授權）（已確認）。
- 真錢包仍延後（MVP 計畫前提 P2）：自動化測試用測試內產生的金鑰與 mock CIP-30，不使用任何個人錢包或助記詞；preprod 上尚無自己的承諾交易（MVP 附件 `spike-a.md`「鏈上樣本 0」），需要真承諾的驗收標為「等真錢包」（已確認）。
- 工具鏈（預設，可推翻）：Biome 負責 lint 與格式化；後端用 Wrangler 與 Miniflare 在本機執行，測試用 `@cloudflare/vitest-plugin`（原名 `@cloudflare/vitest-pool-workers`，0.23.0 標為 deprecated 並改名，步驟 8 於 2026-10-19 查核改用）；bundle 存 R2、紀錄存 D1、IP 突發限流用 Rate Limiting binding（計數只在單一機房內、不精確，週期只能 10 或 60 秒，見 [文件](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)，2026-10-18 查核），到期清理用 Cron Triggers（原為 Koios 全域日預算預設的單一 Durable Object 計數器，理由隨 PD7 消失，存廢依 PD8），讀取時另檢查 `expires_at`。新增套件屬下載，版本鎖在 lockfile。
- 開發期 metadata label 改用 [CIP-10 registry](https://github.com/cardano-foundation/CIPs/blob/master/CIP-0010/registry.json) 未登記的數字（預設，可推翻；步驟 4 選定並記錄查詢日期）；CIP-10 註冊留給 v1 凍結（MVP 計畫 D7）。
- 安全參數：簽章 payload 5 分鐘有效、nonce 一次性（依 [CIP-93](https://cips.cardano.org/cip/CIP-0093) 的建議時間窗）；不用 cookie（[OWASP CSRF Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)）。

**驗收基線：** commit `32d289c` 上 `make check` 全綠：lint、typecheck、13 個測試、10 組 Python vectors、`check_plan.py` OK（2026-10-18 實跑）。瀏覽器 E2E（`tools/browser-check.mjs`）與 `tools/mutation-check.mjs` 本次未跑，由步驟 1 建立基線。已知問題列在附件 `inventory.md`，依各自的處置在本計畫內修。

## 本階段依賴的不變量

沿用 MVP 計畫的 I1–I9；PD3 改寫 I5、I7（步驟 5 執行）。本計畫新增：

| 不變量 | 依賴它的機制（新系統先寫預計的模組） |
|---|---|
| B1 驗證不依賴後端：verifier 不引用後端模組；CLI 沒有專案預設 indexer，只直連使用者以 `--indexer` 指定的 indexer 與 drand relay（PD7）；後端與專案 Dolos 停擺不影響 PASS 判定 | `packages/verifier/index.ts`（不帶預設 indexer）、`packages/beacon/index.ts` 的 `fetchBeacon`、`apps/verifier-cli/index.mjs` 的 `--indexer` 解析、`apps/api/`；邊界由各套件 `package.json` 的 dependencies 與 `biome.json` 的 `noUndeclaredDependencies`、`noRestrictedImports`（禁止離開套件目錄的相對路徑）守住 |
| B2 後端不簽署、不送出交易、不持有私鑰、不產生 randomness、不判定 PASS／FAIL、不改寫 indexer 回應 | `apps/api/src/index.ts`（步驟 9 起沒有轉發 indexer 或送出交易的路由，`apps/api/test/index.test.ts` 斷言不發出任何請求）、`apps/web/cardano.ts` 的 `submitTx`（錢包送出） |
| B3 後端不存密碼、email、OAuth token 或 session token；只存一次性 nonce 的使用紀錄（PD4） | `apps/api/src/auth.ts`（nonce 以 HMAC 簽發、不儲存；`used_nonces` 只存通過驗證的使用紀錄）、`apps/api/migrations/0004_owner_operations.sql` |
| B4 只代管已上鏈承諾、通過 `validateBundle` 的 bundle；代管紀錄以 `txHash` 為主鍵、owner 由該筆交易推導，bytes 以 bundleHash 定址並以參照計數回收；擁有者刪除只移除自己的紀錄，以 bundleHash 為鍵的 tombstone 只用於營運端下架 | `apps/api/src/bundles.ts`（預計）、`packages/protocol/index.ts` 的 `validateBundle`、D1 schema |
| B5 保存有期限：bundle 到 round 後 12 個月，每次延長 12 個月、總計不超過 round 後 36 個月（PD4）；伺服器草稿 30 天 | `apps/api/src/retention.ts`（預計）、Cron Trigger |
| B6 任何列舉頁快取（Workers proxy 或 Dolos 前的 reverse proxy，是否存在依 PD8）不得讓唯一性列舉漏掉交易：Blockfrost 形狀以 page／count 分頁，位置仍隨 rollback 位移，所以列舉頁只有在整頁交易都深於協定的 `CONFIRMATIONS` 時才快取（未滿頁與含淺層交易的頁都不快取）；以 txHash 為鍵的 CBOR 回應可長期快取 | PD8 A 後沒有任何列舉快取（Workers proxy 已移除，`deploy/dolos-proxy/nginx.conf` 不設 `proxy_cache`）；日後加快取時守此規則、`packages/chain/index.ts` 的 `findCommitments` |

    - D1／R2 的順序（review M2，2026-10-20；設計註解在 `bundles.ts`「Writing and deleting bytes」）：D1 與 R2 沒有共同交易、R2 沒有條件式刪除，所以三個機制各守一種交錯。（a）上傳寫完 bytes 後確認紀錄仍在：下架或刪除若落在 INSERT 與寫 R2 之間，寫入會把剛刪掉的物件寫回，確認時看到紀錄不在就再刪一次（有 tombstone 時直接刪，因為之後不可能再有紀錄），回 410／409。（c）刪 bytes 前在 D1 `collecting` 表 claim 該 hash：claim 只在沒有紀錄指向它時插得進去，claim 存在時紀錄插不進去（上傳回 409，重試即可），所以刪除不會打到讀完參照數之後才插入的上傳；刪完才釋放 claim。（b）Cron reconciliation：claim 超過 `CLAIM_STALE`（1 小時；假設持有者在 1 小時內完成 R2 刪除，推論）就由 Cron 刪 bytes 並釋放；再以 `reconcile_cursor` 記住位置，每次掃 R2 一頁（1,000 個 key），經 `collect` 刪沒有紀錄指向的物件，永遠不刪有紀錄的。必要條件：D1 與 R2 分屬兩個儲存；若改成同一個有交易的儲存，claim 表與寫後確認就沒有存在理由，reconciliation 仍是刪除失敗的補救。
    - 檢查順序（review L2）：不需讀鏈的檢查（大小、hash、canonical、`validateBundle`、tombstone）都在讀鏈之前，所以 indexer 只會為合法的 canonical bundle 被讀；反過來先讀鏈，任何人每個請求都能換到專案 Dolos 的讀取。代價是沒有承諾也能讓每個請求花 `validateBundle` 的 CPU（上限由 `BUNDLE_BYTE_LIMIT` 決定，見 PD2）；後端寫入路由依 IP 的限流屬步驟 11。
    - 後端讀鏈：`INDEXER_URL`（wrangler var，本機 `http://127.0.0.1:3010`）加回，只給上傳門檻用、不是轉發路由（BR-01 不變）；必要條件寫在 `bundles.ts`：代管只收鏈上承諾的 bytes（B4）；若代管不再要求鏈上承諾，這個設定就沒有存在理由。用的是 `@giveaway/chain` 的同一份讀取，`biome.json` 依步驟 6 記下的觸發條件把 Cardano SDK 禁用名單加到 `apps/api`。
